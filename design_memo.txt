For this assignment, I created a contact management system using a hash table instead of Python's built-in dictionary. I think a hash table is a good choice for this type of system because it allows us to search for contacts quickly without having to go through every single contact. Instead, the hash function takes the person's name and calculates an index where their information should be stored. This makes finding a contact much more efficient, especially when the number of contacts increases.

One issue I had to account for was collisions, which happen when two different names end up at the same index. To handle this, I used separate chaining with linked lists. Basically, if two contacts have the same index, they can both be stored there by connecting their nodes together. When searching for a contact, the program checks the nodes at that index until it finds the matching name. I also made sure that adding a contact with an existing name updates their phone number instead of creating a duplicate.

I think an engineer would choose a hash table over a regular list when fast searching is the main priority. A list might be simpler, but searching through a large list can take longer. A tree can also be useful, especially when the data needs to stay sorted, but for a contact system where we mainly need to add and find names, I think a hash table makes more sense.
